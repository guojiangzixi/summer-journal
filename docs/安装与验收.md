# 夏日手札 · 安装到手机 & 验收指引

> 目标：把 `code/` 里的工程装到你自己的荣耀手机上跑起来，并对照清单完成验收。
> 适用对象：会用 Android Studio 的人（不需要是 Android 开发）。

---

## 手机只需要 1 个文件

**答案：`SummerJournal-debug.apk`。就这一个。**

源码、Gradle 配置、文档、设计稿 HTML —— **一个都不要发到手机上**。手机不认识 `.kt` / `.gradle.kts`，发过去只是占内存，也装不出任何东西。

| 文件 | 发到手机？ | 为什么 |
|---|---|---|
| **`SummerJournal-debug.apk`** | ✅ **唯一需要** | 系统认这个格式，点一下就能装 |
| `code/` 全部源码（35 个 .kt / 12 个 .xml / 4 个构建文件） | ❌ 不要 | 源码是用来**编译**的，编译在电脑上做 |
| `夏日手札_高保真原型.html` | ❌ 不用 | 15 屏设计稿，在电脑上看 |
| `开发文档.md` / `安装与验收.md` / `code/README.md` | ❌ 不用 | 给你自己看的 |

**APK 从哪来？先在电脑上编一次。** 我把这一步压成了一条命令：

```bash
# Windows：双击
code/build-apk.bat

# macOS / Linux：
./code/build-apk.sh
```

跑完后 APK 会**自动复制到**一个很好找的位置：

```
夏日手札-Android/APK/SummerJournal-debug.apk
```

看到这个文件，就可以往手机发了。

> 之所以要你自己编，而不是我直接给你一个 APK：**能装的包必须用你自己的签名**。用别人的签名给你，今天能装，但以后想更新、想上架全会卡住（签名不匹配 = 只能卸载重装、数据清空）。详见第 5 节。

## 传到手机的三种方式

### 方式 1：数据线 + adb（不发文件，最快）

```bash
adb install -r 夏日手札-Android/APK/SummerJournal-debug.apk
```

手机要开「开发者选项 → USB 调试」，插线后弹「允许 USB 调试」点允许。**整条链路不需要往手机里放任何文件。**

### 方式 2：微信 / QQ 传给自己（最省事）

把 APK 发到「文件传输助手」→ 手机微信里点开 → 用其他应用打开 → 安装。

> ⚠️ **必踩的坑**：微信会把 APK 二次压缩或改名成 `SummerJournal-debug.apk.1`。如果手机上点不开，去文件管理里把它**改名去掉末尾的 `.1`**，恢复成 `.apk` 再点。

### 方式 3：数据线拷文件

把 APK 拷到手机的 `Download/` 目录 → 手机上打开「文件管理」→ 找到它 → 点击安装。

## 荣耀手机允许安装（首次需要做一次）

```
设置 → 安全 → 更多安全设置 → 安装外部来源应用
   → 找到你用来打开的 App（微信 / QQ / 文件管理）→ 允许
```

Android 13+ 上这一步是**按来源应用**授权的，不是全局开关 —— 用微信打开就要给微信授权，用文件管理打开就要给文件管理授权。

装完后：

- 桌面会出现「夏日手札」图标（晚霞渐变底色 + 手札图形）
- APK 文件本身可以删掉了，已经装进系统
- 想卸载：长按图标拖到「卸载」

## 附：今天还编不出 APK，但也想在手机上先看一眼设计

有一条**零编译**的路子 —— 把设计稿当网页跑在手机浏览器里：

1. 把 `夏日手札_高保真原型.html` 发到手机（微信 / QQ 都行）
2. 手机上**用 Chrome 打开**这个文件（微信里点「用其他应用打开 → Chrome」）
3. Chrome 菜单 → **添加到主屏幕**
4. 桌面会多一个图标，点开就是全屏的 15 屏设计稿

**适合用来验收什么**：
- 390px 宽度下字够不够大、课程名会不会被截断
- 那套晚霞配色在真实屏幕上是不是够「柔和」（手机屏显色和电脑显示器差很多）
- 荣耀的状态栏/挖孔会不会挡住内容
- 深色模式下看着刺不刺眼

**不适合用来验收什么**（说清楚，免得误会）：
- 它不是 App。15 屏是**并排的设计稿**，不能真的点进课表、存不了日程、没有真实数据
- 关掉 Chrome 就没有了，不会自己更新

想「点得动、存得住」的东西，还是得走上面第 1 节，把 APK 编出来。

## 2. 路线 A（推荐）：Android Studio 直接跑到手机

1. Android Studio → **Open** → 选中 `夏日手札-Android/code` 目录
2. 首次打开会提示 **Gradle Sync**，等它下载依赖（约 3–8 分钟，取决于网速）
3. 手机用数据线连电脑，弹「允许 USB 调试」→ 允许
4. 顶部设备下拉里选中你的手机 → 点绿色 ▶ **Run**
5. 首次运行会自动装到手机，之后改代码再点 Run 就是增量更新

**Sync 阶段会看到什么**：底部进度条走「Downloading dependencies…」，首次约 3–8 分钟。
工程里已经配好阿里云 Maven 镜像（`settings.gradle.kts`），国内下载会快很多。
跑完的标志是底部不再转圈、左侧能看到 `app/java/com.summer.journal/` 下的文件。

> 之前那句「本工程没带 gradle-wrapper.jar」的提示已经**不再适用** ——
> wrapper 的 jar 和 `gradlew` / `gradlew.bat` 都已补齐，工程开箱即可 `./gradlew assembleDebug`。

## 4. 路线 C（最稳，遇到构建问题就用这条）

如果你在 Sync 上反复卡住，用这个办法绕开所有工程配置问题：

1. Android Studio → **New Project** → **Empty Activity**（Compose，Kotlin）
2. package name 填 `com.summer.journal`，minSdk 选 **26**
3. 等新工程 Sync 成功（这一步验证了你的环境是好的）
4. 把这个仓库里 `code/app/src/main/` 下的内容，**整体覆盖**到新工程的 `app/src/main/`
5. 用 `code/gradle/libs.versions.toml` 覆盖 `gradle/libs.versions.toml`
6. 用 `code/app/build.gradle.kts` 里的 `dependencies { }` 块替换新工程的同名块
7. 删掉新工程自带的 `MainActivity.kt`（被我们覆盖了）和 `ui/theme/` 下的模板文件
8. Sync → Run

## 5. Release 签名（要发出去或长期自用时做）

```bash
keytool -genkey -v -keystore summer-journal.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias summerjournal
```

然后在 `app/build.gradle.kts` 里加：

```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file("../summer-journal.jks")
            storePassword = System.getenv("SJ_STORE_PASS")
            keyAlias = "summerjournal"
            keyPassword = System.getenv("SJ_KEY_PASS")
        }
    }
    buildTypes {
        release { signingConfig = signingConfigs.getByName("release") }
    }
}
```

⚠️ **`summer-journal.jks` 和密码一定要单独备份**。丢了就永远无法发布同名 App 的更新，用户只能卸载重装。

```bash
./gradlew assembleRelease   # 产物：app-release.apk
./gradlew bundleRelease     # 产物：app-release.aab（上架用）
```

## 7. 已知缺口（**这些不是 bug，是 v1.0 的既定范围**）

装上去之后你一定会碰到下面这些，先说清楚免得当成故障：

| 项 | 现状 | 影响 |
|---|---|---|
| **农历节日 / 调休** | `HolidayProvider` 只实现了固定日期的元旦 / 劳动节 / 国庆；春节、清明、端午、中秋**故意留空** | 农历节日不显示。宁可少显示也不显示错的日期 —— 调休安排必须每年从国务院通知更新 |
| **课表教务导入** | 完整链路（WebView 登录 + Cookie 复用 + Jsoup 解析 + 文本降级）已写好，但**解析规则需要拿真账号的页面验证** | 点导入能打开登录页，但解析结果可能为空（教务页面结构与我的假设不同） |
| **课表字段编辑** | 点空格子生成的是占位课程「新课程」，还不能改名字/教师/教室 | 需要补编辑弹窗（`TimetableViewModel.addCourse` 已支持全部字段，只缺 UI） |
| **学期切换 UI** | 数据层支持多学期，但界面只有「当前学期」 | 需要补学期列表页 |
| **手札附件** | `AttachmentStore` 四类附件（音频/图片/文件/表格）+ `RecordingService` 录音都已实现；UI 只接了「换封面」和图片 | 音频/文件/表格的入口还没接上 |
| **音频播放** | 未接。计划用 Media3 应用内播放 | 无 |
| **日历视图** | 只有月视图 + 当日列表；年/周视图未做 | 需要补 |
| **天气图标** | 用的是 Unicode 天气符号（☀⛅☔） | 不同 ROM 渲染差异大，**建议换成 vector drawable** |
| **深色模式** | 颜色方案已定义，但预设背景色在深色下的映射还没逐屏核对 | 可能有个别地方对比度不足 |
| **云同步** | 未实现 | 换手机靠系统备份恢复 |

## 8. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| Sync 失败：`Could not find com.android.tools.build:gradle` | 网络到 Google Maven 不通 | 配镜像，或在 AS 里挂代理 |
| 编译报 `Unresolved reference: xxx` | 某个文件没拷全 | 对照本文档的 35 个 kt 文件清单核对 |
| 装了但打开就崩 | 大概率是 Hilt 没生成代码 | 确认 `ksp(libs.hilt.compiler)` 和 `ksp(libs.hilt.compiler.androidx)` 都在，然后 `Build → Clean Project` |
| 天气一直不显示 | 没给定位权限且没手选城市 | 我的 → 城市 → 手动搜索 |
| 天气显示但温度离谱 | 定位解析到了别的城市 | 手动选城市覆盖 |
| 教务导入后课表是空的 | 页面结构和我假设不一致 | 用 AS 的 App Inspection / 把页面 HTML 存下来，改 `CsuJwxtParser` |
| 提醒不响 | 权限没给全 | 我的页看「已完成 x/3」，荣耀还要额外配自启动 |
| 提醒晚几分钟 | 精确闹钟未授权 | 我的 → 精确闹钟 → 去设置 |
| 模糊滑块没反应 | Android 11 及以下不支持 | 预期行为，见 6.1 备注 |
