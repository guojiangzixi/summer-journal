## 2. 技术选型

### 2.1 结论

**Kotlin + Jetpack Compose 原生开发。**

### 2.2 为什么不是跨端

| 方案 | 优点 | 对本项目的致命点 |
|---|---|---|
| **Kotlin + Compose（选定）** | 系统能力全量可用：精确闹钟、通知渠道、SAF 文件、后台音频、WebView Cookie 保持；包体小、动画顺 | 需要 Android 单一岗位，成本略高 |
| Flutter | 一套代码多端，UI 一致 | 教务导入要 WebView + JS 注入，跨端桥接成本高；精确闹钟 / 通知渠道仍需写平台通道；包体 +15MB |
| uni-app / 小程序 | 上手快 | **做不了**：精确提醒、后台录音、文件系统访问、教务 WebView 登录，全部会卡住 |

本项目三个硬需求——**精确提醒**、**教务系统登录抓取**、**本地音视频文件**——都贴着系统能力走，跨端框架会在每一个上多花一周。所以选中原生。

**第三方服务**

| 服务 | 用途 | 成本 | 备注 |
|---|---|---|---|
| **Open-Meteo**（选定） | 实时天气 / 逐小时 / 7 天 / 15 天 | **完全免费，无需注册、无需 API Key、无需签名** | 非商业用途免费；一次 GET 就能拿到全部字段 |
| **Open-Meteo Air Quality** | PM2.5 / PM10 / O₃ / NO₂ / 欧洲 AQI | 同上，免费无需 Key | 同域名，同一套参数风格 |
| 生活指数 | 紫外线 / 穿衣 / 运动 / 洗车 / 晾晒 | — | **不调接口**，用 UV 指数 + 体感温度 + 降水概率在本地算，见 §5.5 |
| 定位 / 地名 | 坐标 ↔ 城市名 | **免费，无内置城市表** | ① 定位取坐标：系统 `LocationManager.getLastKnownLocation`（不依赖 GMS）② 坐标→地名：系统 `Geocoder`（AOSP 自带）③ 手动搜城市：Open-Meteo Geocoding API（同域名家族，免 Key）|
| 中南大学教务系统 | 课表数据源 | — | **无公开 API**，见 §5.1 |

**为什么换成 Open-Meteo**：和风天气 / 彩云 / 心知都需要注册账号拿 Key、绑包名 + SHA1，还有每日调用上限；Open-Meteo 是纯 HTTP GET、免鉴权、无日限（有礼貌限流），个人 App 完全够用，也不需要把 Key 塞进 APK（塞 Key 还有被反编译盗用的风险）。

请求示例（不需要任何 Key、任何 header）：

```
GET https://api.open-meteo.com/v1/forecast
    ?latitude=28.1717&longitude=112.9382
    &current=temperature_2m,relative_humidity_2m,apparent_temperature,
             is_day,precipitation,weather_code,wind_speed_10m,wind_direction_10m
    &hourly=temperature_2m,precipitation_probability,weather_code,uv_index
    &daily=weather_code,temperature_2m_max,temperature_2m_min,
           precipitation_probability_max,uv_index_max,sunrise,sunset
    &timezone=Asia%2FShanghai
    &forecast_days=7

GET https://air-quality-api.open-meteo.com/v1/air-quality
    ?latitude=28.1717&longitude=112.9382
    &current=pm2_5,pm10,ozone,nitrogen_dioxide,european_aqi
    &timezone=Asia%2FShanghai
```

> 注意：Open-Meteo 的天气描述是 **WMO Weather Code**（0=晴、3=阴、61=小雨、80=阵雨…），需要本地映射成中文 + 图标，映射表在 `WeatherCode.kt` 里。
>
> **地名也不内置任何城市表**。预设一个城市意味着可能给用户看错地方的天气，比「暂时没有天气」糟糕得多——所以城市名只有两个来源：系统定位 + 系统 `Geocoder`（反向）、用户手动搜索 + Open-Meteo Geocoding（正向）。两条路都拿不到时，UI 明确提示「请手动选择城市」，**绝不回退到某个默认城市**。

## 3. 架构设计

### 3.1 分层

```
┌─────────────────────────────────────────────────┐
│  UI 层  (Compose + ViewModel)                    │
│  calendar / timetable / memo / weather / theme   │
└───────────────┬─────────────────────────────────┘
                │ StateFlow<UiState> ↑   Event ↓
┌───────────────▼─────────────────────────────────┐
│  Domain 层  (纯 Kotlin，无 Android 依赖)         │
│  Model · UseCase · 周期展开算法 · 冲突检测        │
└───────────────┬─────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────┐
│  Data 层                                         │
│  Room(本地库) · DataStore(设置) · Remote(天气/教务) │
│  Repository 统一出口，Flow 驱动 UI                │
└─────────────────────────────────────────────────┘
```

规则：
- UI 层只依赖 ViewModel 暴露的 `StateFlow<XxxUiState>`，不直接碰 Repository。
- Domain 层不 import 任何 `android.*`，方便单元测试与未来复用。
- Data 层是唯一知道数据库 / 网络 / 文件系统的地方。

### 3.2 包结构（单模块 + 分包）


## 4. 数据模型

### 4.1 领域模型（节选）

```kotlin
// 学期
data class Semester(
    val id: Long, val name: String,          // "2026–2027 第一学期"
    val startDate: LocalDate, val totalWeeks: Int,  // 第 1–18 周
    val isCurrent: Boolean
)

// 课程（一条 = 课表上的一个格子）
data class Course(
    val id: Long, val semesterId: Long,
    val name: String, val teacher: String?, val room: String?,
    val dayOfWeek: Int,                      // 1=周一 … 7=周日
    val periodStart: Int, val periodEnd: Int,// 节次，如 3..4
    val weekParity: WeekParity,              // ALL / ODD / EVEN
    val weekRange: IntRange,                 // 1..16
    val colorKey: String                     // "teal" / "violet" / ...
)

// 日程
data class ScheduleEvent(
    val id: Long, val title: String, val note: String?,
    val startAt: LocalDateTime, val endAt: LocalDateTime?,
    val allDay: Boolean, val location: String?,
    val repeatRule: RepeatRule, val colorKey: String,
    val reminders: List<Duration>            // 提前量，可多个
)

// 手札
data class Memo(
    val id: Long, val title: String,
    val coverUri: String?,                   // 可换的自定义封面
    val body: String, val tags: List<String>,
    val createdAt: LocalDateTime, val updatedAt: LocalDateTime
)

// 附件
data class Attachment(
    val id: Long, val memoId: Long, val type: AttachType, // AUDIO/IMAGE/FILE/SHEET
    val localPath: String, val displayName: String,
    val sizeBytes: Long, val durationMs: Long?, val sheetJson: String?
)

// 背景主题
data class BackgroundTheme(
    val colorKey: String,                    // "warm_white" / "dusk_purple" ...
    val imagePath: String?,
    val blurDp: Int, val scrimAlpha: Float,
    val scope: BackgroundScope,              // ALL / CALENDAR_ONLY / AUTO_BY_TIME
    val autoInvertText: Boolean
)
```

### 4.2 Room 表结构

| 表 | 关键字段 | 索引 |
|---|---|---|
| `semester` | id, name, start_date, total_weeks, is_current | `name` unique |
| `course` | id, semester_id, name, teacher, room, day_of_week, period_start, period_end, week_parity, week_start, week_end, color_key | `(semester_id, day_of_week, period_start)` |
| `schedule_event` | id, title, note, start_at, end_at, all_day, location, repeat_rule, color_key | `start_at` |
| `event_reminder` | id, event_id, offset_minutes, fired | `(event_id)` |
| `memo` | id, title, cover_uri, body, created_at, updated_at | `updated_at` |
| `memo_tag` | memo_id, tag | `tag` |
| `attachment` | id, memo_id, type, local_path, display_name, size_bytes, duration_ms, sheet_json | `(memo_id, type)` |
| `weather_cache` | city_key, payload_json, fetched_at | `city_key` unique |

> `repeat_rule` 存 RFC 5545 的 RRULE 子串（如 `FREQ=WEEKLY;BYDAY=MO,TH`），复用成熟语义，不自己发明规则格式。
> `week_parity` 用 `@TypeConverter` 存 enum 名，方便以后给数据库做手工排查。

### 4.3 关键约束

- 同一学期内，同一天同一节次**允许多门课并存**（单双周会交错），不做 DB 层唯一约束，冲突只在导入 / 新增时用 Domain 层检测并提示。
- 课表周期展开成具体日期时才计算单双周，DB 存的是「规则」而不是「每一节课」，避免一学期 500+ 条冗余。
- 附件只存**本地相对路径**，不存绝对路径——避免 Android 沙箱路径变化导致数据失效。

## 5. 关键流程

### 5.1 课表导入：教务系统（**全项目技术难点**）

**前提**：中南大学教务系统 `http://csujwc.its.csu.edu.cn/jsxsd/xskb/xskb_list.do?Ves632DSdyV=NEW_XSD_WDKB` 没有公开 API，页面是服务端渲染的 HTML 表格，且需要登录态。

**结论：不要用 OkHttp 硬抓。**

原因：登录有加密参数和 CSRF token，逆向成本高且随学校升级随时失效。用 **WebView 让用户正常登录**，登录完成后从 WebView 里读 Cookie，再用同一 Cookie 请求课表页——这是最稳、最不容易被反爬打掉的路径。

```
[用户点「一键导入本学期课表」]
        │
        ├─1. 打开 WebView，加载 jsxsd 登录页
        │     · 用户自己输学号 / 密码 / 验证码
        │     · 我们不做自动填表，不存密码（合规风险最低）
        │
        ├─2. 监听 WebView 页面跳转（WebViewClient.shouldOverrideUrlLoading）
        │     命中登录后才会出现的路径（含 "framework" / "xskb"）→ 判定登录成功
        │
        ├─3. CookieManager.getInstance().getCookie(url)
        │     拿到 JSESSIONID 等凭证
        │
        ├─4. OkHttp 带 Cookie 请求 xskb_list.do?Ves632DSdyV=NEW_XSD_WDKB
        │     得到课表 HTML
        │
        ├─5. Jsoup 解析
        │     · 取表头：星期几的列顺序
        │     · 取左侧行：节次（1-2 / 3-4 / …）
        │     · 每个格子：文本形如 "高等数学A(二)\n张明\n科南201\n1-16周"
        │       用正则拆出 课程名 / 教师 / 教室 / 周次
        │
        ├─6. 归一化
        │     · 星期 → dayOfWeek（教务口径「星期日」→ 内部 7）
        │     · 节次 "3-4"        → periodStart=3, periodEnd=4
        │     · 周次 "1-16周"     → weekRange=1..16
        │     · 周次 "1-16周(单)" → weekParity=ODD
        │
        ├─7. 与库里已有课程做 diff，弹「确认导入」列表
        │     用户可以逐条勾选 / 取消，也可以改教室
        │
        └─8. 落库，标记该学期 lastSyncedAt
```

**降级路径**（必须在 UI 上给出）：
1. 教务改版导致解析失败 → 提示「解析失败，已保存页面快照，可粘贴文本导入」；提供**纯文本粘贴框**，用同一套正则解析。
2. 用户不想登录教务 → 手动录入 / Excel·CSV 导入 / 截图表。

**合规与安全**
- 密码只在 WebView 里由用户输入，**App 永不读取、不落盘、不上传**。
- Cookie 只存在内存 + WebView 自己的 CookieStore；导入完成后 `CookieManager.removeAllCookies()`。
- 用户协议里写明「课表数据来自学校教务系统，仅供个人查看」。

```kotlin
fun Course.occurrences(semesterStart: LocalDate): List<LocalDate> {

    return weekRange.filter { week ->
        when (weekParity) {

            WeekParity.ODD  -> week % 2 == 1
            WeekParity.EVEN -> week % 2 == 0
        }
```

### 5.3 提醒调度

**为什么不用 WorkManager 做提醒**：WorkManager 的延迟是「几分钟级」的，用来做 09:00 的课前提醒会迟到。提醒必须用 `AlarmManager.setExactAndAllowWhileIdle`。

```
保存日程 / 导入课表
        ↓
ReminderScheduler.rescheduleAll()
        ↓
  查询未来 7 天内所有「需要提醒的时刻」（日程提醒 + 上课提醒）
        ↓
  每个时刻 setExactAndAllowWhileIdle(RTC_WAKEUP, triggerAtMillis, PendingIntent)
        ↓
  到点 → ReminderReceiver → NotificationCompat 发通知（含「查看」与「稍后提醒 10 分钟」两个 action）
        ↓
  开机 / 应用升级 / 时区变化 → BootReceiver / ACTION_TIMEZONE_CHANGED → 重新排
```

**荣耀（MagicOS）适配要点**（这是国内 Android 最容易被忽略的坑）：

| 问题 | 现象 | 对策 |
|---|---|---|
| 后台限制 | 应用被冻结，闹钟不响 | 引导用户把 App 加入「应用启动管理 → 手动管理」，并允许「自启动 / 关联启动 / 后台活动」 |
| 通知被折叠 | 提醒只在通知栏闪一下 | 用**高优先级通知渠道**（`IMPORTANCE_HIGH`）+ 设为「允许横幅」 |
| 省电模式 | 夜间提醒不触发 | 申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，并在设置页提供入口 |
| 精确闹钟权限 | Android 12+ 需 `SCHEDULE_EXACT_ALARM` | 首次开启提醒时用 `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` 引导授权；未授权时降级为「最多晚 10 分钟」并明确告知用户 |

首启时用**一屏引导**把这三件事做完（`BatteryOptGuideScreen`），比事后报 bug 划算得多。

### 5.4 附件处理

| 类型 | 来源 | 落盘处理 |
|---|---|---|
| 音频 | Media3 Recorder 录制 | 存 `.m4a`（AAC 64kbps 单声道），`internalFiles/attachments/audio/{uuid}.m4a`；写 `durationMs` |
| 图片 | AndroidX PhotoPicker（`PickVisualMedia`） | 长边压到 2048px、JPEG q=85，**保留原图**到 `originals/`；列表只读缩略图 |

- 附件总占用超 2 GB 时，在设置页给出「清理未引用附件」入口。
- 删除手札时**不立即删文件**，先标记为孤儿，24 小时后由 WorkManager 任务清理——防误删。

### 5.5 天气（Open-Meteo，零成本零配置）

**数据来源**：Open-Meteo，两个域名、两次 GET、无需 Key、无需注册。

```
[App 启动 / 下拉刷新 / 每 30 分钟 WorkManager]
        ↓
① 定坐标
   系统 LocationManager.getLastKnownLocation（NETWORK → PASSIVE → GPS 取最新那个）
   只取一次，零耗电，不申请前台服务，不依赖 Google Play 服务
        ↓ 无权限 / 无缓存坐标 → **不用默认城市**，直接进「手动选城市」空态
   坐标 → 地名：系统 Geocoder 反向解析（AOSP 自带，免 Key）
        ↓ Geocoder 不可用（部分国内 ROM 会 isPresent()==false）
   仍然展示天气，标题显示「当前位置」；用户可点开设置手动搜索城市
        ↓
② 读缓存（Room.weather_cache）
   命中且 < 30 分钟 → 立刻 emit，界面秒开
        ↓ 无论是否命中，都继续请求刷新（stale-while-revalidate）
③ 并发两个请求（Retrofit + coroutineScope { async } ）
   api.open-meteo.com/v1/forecast           → current / hourly / daily
   air-quality-api.open-meteo.com/v1/air-quality → current AQI + 四项污染物
        ↓
④ 归一化
   · WMO weather_code → 中文描述 + 图标（WeatherCode.kt 映射表）
   · 逐小时数组 → 从「当前小时」起取 24 条
   · daily 数组 → 7 天，含温度区间与降水概率
   · 生活指数：本地算，不调接口（见下）
        ↓
⑤ 写回缓存 + emit
```

**城市名怎么来：没有内置表，两条路**

```
① 自动（定位）  LocationManager.getLastKnownLocation → 坐标
                     ↓
                Geocoder.getFromLocation(坐标) → "长沙市 · 岳麓区"
                     ↓ Geocoder.isPresent() == false（部分国内 ROM）
                标题显示「当前位置」，天气照常可用，并提示可手动选城市

② 手动（搜索）  用户输入「长沙」
                     ↓
                GET https://geocoding-api.open-meteo.com/v1/search

                     ↓   ← 同样免注册、免 Key
                给出候选列表，用户点选
```

```kotlin
// data/location/CityResolver.kt
@Singleton
class CityResolver @Inject constructor(
    @ApplicationContext private val context: Context,
    private val okHttpClient: OkHttpClient,
) {
    /** 只读 lastKnownLocation：同步、零耗电、不依赖 GMS，对天气场景足够 */
    @SuppressLint("MissingPermission")
    fun lastKnownCoordinate(): Coordinate? {
        if (!hasLocationPermission()) return null
        val lm = context.getSystemService(Context.LOCATION_SERVICE) as? LocationManager ?: return null
        return listOf(NETWORK_PROVIDER, PASSIVE_PROVIDER, GPS_PROVIDER)
            .mapNotNull { runCatching { lm.getLastKnownLocation(it) }.getOrNull() }
            .maxByOrNull(Location::getTime)
            ?.let { Coordinate(it.latitude, it.longitude) }
    }

    /** 反向地理编码；解析不出来就返回 null，**绝不编一个城市名** */
    suspend fun resolveName(c: Coordinate): String? { /* Geocoder，见源码 */ }

    /** 正向搜索：Open-Meteo Geocoding，免 Key */
    suspend fun search(keyword: String): List<City> { /* OkHttp + kotlinx.serialization */ }

    suspend fun resolveCurrentCity(): City? {
        val coordinate = lastKnownCoordinate() ?: return null
        val name = resolveName(coordinate) ?: return null
        return City(name, coordinate.latitude, coordinate.longitude)
    }
}
```

> 为什么不缓存城市名到 DataStore 当「上次位置」：定位失败时用**已经过期的**城市名，用户可能已经跨城了。宁可让他手动选一次，也不要给错。定位成功后的坐标会随天气一起缓存（`weather_cache.city_key`），下次冷启动能秒开——这是缓存正确用法。

**生活指数：本地推算，不调接口**

| 指数 | 算法 |
|---|---|
| 紫外线 | `uv_index_max` ≤2 弱 / 3–5 中等 / 6–7 强 / ≥8 很强 |
| 穿衣 | 按体感温度分档：<5 羽绒 / 5–12 厚外套 / 13–19 长袖 / 20–26 薄长袖 / >26 短袖 |
| 运动 | 降水概率 <30% 且 15 ≤ 体感 ≤ 28 且 AQI ≤ 100 → 适宜，否则降档 |
| 洗车 | 未来 24h 降水概率 ≥ 40% → 不宜 |
| 感冒 | 昼夜温差 > 10℃ 或 体感 < 10℃ → 易发，否则少发 |
| 晾晒 | 降水概率 <20% 且 湿度 <75% → 适宜 |

**缓存与降级**
- 缓存 TTL 30 分钟；`WorkManager` 每 30 分钟静默刷新（仅 Wi-Fi 或任何网络均可，流量极小）。
- **任何失败都只隐藏天气卡，绝不让日历页整体报错**。天气卡失败态是一个「重试」按钮。
- Open-Meteo 免费版有礼貌限流（非严格配额）。触发限流时读旧缓存并在天气详情页底部标注「数据更新于 xx:xx」，不弹错误。
- 断网时如果连缓存都没有 → 隐藏天气区块（不留空壳）。

**「受天气影响的日程」**（Domain 层纯函数）：遍历未来 7 天日程，若 `降水概率 ≥ 50%` 且日程带「户外」标签 → 产出提示条「建议改室内」；若日程地点是室内则显示「不受影响」。

### 5.7 权限体系（按需求重点展开）

**三条铁律**

1. **用到才要**。不在启动页批量弹框。天气定位到天气卡时才要，录音到按「录音」键时才要。
2. **每个权限都有降级路径**。拒绝不等于功能不可用，只等于「少了某个便利」。
3. **分清「运行权限」和「特殊权限」**。普通运行时权限用 `ActivityResultContracts` 一次搞定；`SCHEDULE_EXACT_ALARM`、电池优化白名单、通知渠道这类要跳系统页的，必须单独设计引导流程。

#### 5.7.1 权限矩阵

| 权限 | 类别 | 申请时机 | 用户拒绝后的降级 | 引导话术（要点）|
|---|---|---|---|---|
| `POST_NOTIFICATIONS` | 运行时（13+） | 用户**首次保存带提醒的日程**时 | 提醒改为「仅应用内横幅 + 日程卡高亮」，并在日程页顶部常驻提示条 | 「不开启通知，提醒只会在你打开 App 时看到」 |
| `SCHEDULE_EXACT_ALARM` | **特殊**（12+ 跳系统页） | 同上，紧接通知之后 | 降级为 `setWindow()`，最多晚 10 分钟，并在设置页标注「提醒可能延迟」 | 「开启精确闹钟才能准点响」 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | **特殊** | 首次保存提醒后，第 2 次进入设置页时 | 提醒在夜间可能不触发；设置页显示「未加入白名单」黄标 | 国内 ROM 必做，见 §5.3 |
| `ACCESS_COARSE_LOCATION` | 运行时 | 天气卡首次可见时（延迟 1.5 秒再问，避免和入场动画抢焦点） | 用上次手选城市 / 内置校区表首项，天气照常显示 | 「用一次定位就能自动匹配校区天气，也可以手动选城市」 |
| `ACCESS_FINE_LOCATION` | 运行时 | **不主动申请**。仅当用户在设置里选「精确到校区」时 | 用粗定位 | — |
| `RECORD_AUDIO` | 运行时 | 点击手札「录音」按钮时 | 该按钮变为「上传已有音频」，其余功能不受影响 | 「录音权限只用于手札录音，音频只存在你手机里」 |
| `CAMERA` | 运行时 | 手札里点「拍照」（**不申请也能用相册**，优先引导相册） | 只能从相册选图 | — |
| `READ_MEDIA_*` | 运行时（13+ 分项） | 手札点「图片 / 音频 / 文件」时**按类型单独申请** | 用 PhotoPicker（**免权限**）——13+ 上优先走 PhotoPicker，根本不申请 | — |
| `RECEIVE_BOOT_COMPLETED` | 普通（安装即得） | — | 无 | — |

> 关键取舍：**Android 13+ 上「选图片」优先用 `PickVisualMedia` / PhotoPicker**，系统相册代选、App 只拿到选中的那一张，**完全不需要 READ_MEDIA_IMAGES**。少一个权限，少一半审核问题，也少一半卸载。

```kotlin
enum class AppPermission(val key: String) {
    NOTIFICATION(Manifest.permission.POST_NOTIFICATIONS),
    EXACT_ALARM(Manifest.permission.SCHEDULE_EXACT_ALARM),
    COARSE_LOCATION(Manifest.permission.ACCESS_COARSE_LOCATION),

sealed interface PermResult {
    data object Granted : PermResult

    data class Denied(val canAskAgain: Boolean) : PermResult
    /** 永久拒绝 —— 必须跳系统设置 */
    data object PermanentlyDenied : PermResult
}
```

```kotlin
// permission/PermissionManager.kt
@Singleton
class PermissionManager @Inject constructor(
    @ApplicationContext private val ctx: Context,
) {
    fun isGranted(p: AppPermission): Boolean = when (p) {
        AppPermission.NOTIFICATION ->
            Build.VERSION.SDK_INT < 33 || ctx.checkSelfPermission(p.key) == PERMISSION_GRANTED
        AppPermission.EXACT_ALARM ->
            Build.VERSION.SDK_INT < 31 ||
                ctx.getSystemService(AlarmManager::class.java).canScheduleExactAlarms()
        else -> ctx.checkSelfPermission(p.key) == PERMISSION_GRANTED
    }

    /** 需要跳系统页的两类特殊权限 */
    fun settingsIntentFor(p: AppPermission): Intent? = when (p) {
        AppPermission.EXACT_ALARM ->
            Intent(Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM, "package:${ctx.packageName}".toUri())
        AppPermission.NOTIFICATION ->
            Intent(Settings.ACTION_APP_NOTIFICATION_SETTINGS)
                .putExtra(Settings.EXTRA_APP_PACKAGE, ctx.packageName)
        else -> null
    }

    /** 国内 ROM：电池优化白名单（拿不到就用厂商自启页兜底） */
    fun batteryOptimizationIntent(): Intent =
        Intent(Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS,
            "package:${ctx.packageName}".toUri())
            .takeIf { (ctx.getSystemService(PowerManager::class.java))
                .isIgnoringBatteryOptimizations(ctx.packageName).not() }
            ?: Intent(Settings.ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS)
}
```

```kotlin
// permission/Compose.kt —— Compose 侧统一入口，避免每个页面各写一遍
@Composable
fun rememberPermissionRequester(
    onResult: (AppPermission, PermResult) -> Unit,
): PermissionRequester {
    val ctx = LocalContext.current
    val launcher = rememberLauncherForActivityResult(
        ActivityResultContracts.RequestPermission()
    ) { granted ->
        // 关键：拿不到「不再询问」的标记时，用 shouldShowRequestPermissionRationale 反推
        val activity = ctx.findActivity()
        val perm = pendingPermission ?: return@rememberLauncherForActivityResult
        val res = when {
            granted -> PermResult.Granted
            activity?.shouldShowRequestPermissionRationale(perm.key) == true ->
                PermResult.Denied(canAskAgain = true)
            else -> PermResult.Denied(canAskAgain = false)
        }
        onResult(perm, res)
    }
    return remember { PermissionRequester(ctx, launcher) { pendingPermission = it } }
}
```

## 9. 打包与上架

- **签名**：用 Android App Bundle (.aab)。国内渠道（华为应用市场 / 荣耀应用市场）走 AGC 上传，需在 AGC 配置签名。
- **HarmonyOS NEXT**：注意——**鸿蒙 NEXT 不兼容 Android APK**。如果后续要覆盖纯血鸿蒙用户，需要单独用 ArkTS 重写，或做 H5 / uni-app 版本。这一点必须在需求评审时就和产品说清楚（建议先只做 Android 版，观察鸿蒙用户占比）。
- **上架材料**：
  - `USE_EXACT_ALARM` 需要说明「日历提醒类应用」用途，否则可能被拒。
  - 隐私政策需列明：天气定位、媒体读取、教务系统 Cookie（仅本地）、附件本地存储。
  - 教务系统导入功能需在描述里写明「数据来自学校教务系统，仅供个人查看」，避免被判为第三方数据爬取。
- **版本节奏**：v1.0 只上 Android；v1.1 加云同步；v1.2 再评估鸿蒙。
