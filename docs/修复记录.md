## 〇、重建说明（重建时新增，便于对照）

重建覆盖的三处额外改动：

1. **录音权限申请**（`MemoDetailScreen.kt`）：详情页点「录音」时先申请 `RECORD_AUDIO`，
   授权后再起前台服务。与 `RecordingService` 的保护圈是**两道独立防线**：
   一道防「没授权就起服务」，一道防「起了但系统仍拒绝」。
2. **定位权限申请**（`MainScaffold.kt`）：天气卡「开启定位」触发
   `ACCESS_COARSE/FINE_LOCATION` 运行时申请。
3. **手札全新入口**（`MemoScreen.kt`）：新建流程从旧 `AlertDialog` 换成
   `MemoCreateSheet`（可选「空白/音频/图片/文件/表格」），并修正创建时序。

## 二、关键根因说明（值得你知道的三处）

### 1. 录音崩溃：一个未被保护的 `startForeground`
```kotlin
// 修复前（RecordingService）
ServiceCompat.startForeground(this, ID, notif, FOREGROUND_SERVICE_TYPE_MICROPHONE)  // ← 裸奔
runCatching { /* MediaRecorder 配置 */ }
```
`MediaRecorder` 那段有 `runCatching`，但真正会抛 `SecurityException` 的 `startForeground` 却在保护圈外 → 异常直达主线程 → 进程死 → 表现为「一点录音 App 就退出」。现已把它纳入保护并优雅降级。

### 2. 图片手札"生成不了"：ActivityResult 生命周期陷阱
Compose 的 `rememberLauncherForActivityResult` 会在所挂载的 Composable 离开组合时**反注册**。
原代码「建壳 → 启动选图器 → 立刻 `onOpen(id)` 跳详情」的次序，导致列表页被销毁、选图回调丢失。
修复：**先等选图结果，再跳详情**。

### 3. 手札"无法分类"：N+1 顾虑引出的另一个 bug
列表为了性能不加载附件明细，但 `Memo.hasImage` 等又依赖附件列表 → 标签永远为空。
修复：一条子查询把类型聚合成 `"AUDIO,IMAGE"` 一次带出，`Memo.kinds` 参与判断，列表与详情结果一致。

## 三、诚实说明

1. **农历为自研离线算法**，覆盖 1900–2100，超出范围返回空（不显示错值，与既有节假日原则一致）。算法已用若干已知闰月（2023 闰二月、2025 闰六月、2028 闰五月）做交叉校验，但**建议在真机上核对 1–2 个已知农历日期**（如 2026 中秋 = 公历 9/25）。
2. **本机定位兜底仅在 Android 11（API 30）及以上生效**；更低版本仍只用系统缓存位置（避免在老机型上引入不稳定代码路径）。
3. 相机/录音/定位都是**系统权限相关行为**，编译通过不代表真机一定顺滑，请按下表点验。
4. 尚未做：纯色背景自定义取色器、24 节气、音频真实波形（沿用既有取舍）。
