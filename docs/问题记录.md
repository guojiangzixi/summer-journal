## 问题 1 · 手札录音一点就崩溃（自动退出）　🔴 高

**现象**：手札页点「录音」→ App 直接退出 / 闪退。

**根因（已读代码确认）**：
- `ui/memo/MemoViewModel.kt` 的 `startRecording(memoId)`（约 L231）直接调 `RecordingService.start(context, ...)`，**全程没有判断 `RECORD_AUDIO` 是否已授权**。
- `data/attachment/RecordingService.kt` 的 `startRecording()` 里：
  ```kotlin
  ServiceCompat.startForeground(this, NOTIFICATION_ID, buildNotification(),
      if (...) ServiceInfo.FOREGROUND_SERVICE_TYPE_MICROPHONE else 0)   // ← 在 runCatching 之外
  runCatching { MediaRecorder(...)... }   // ← 只有 MediaRecorder 部分被保护
  ```
- **Android 14+（API 34）起**：未授权 `RECORD_AUDIO` 就启动 `microphone` 类型的前台服务，系统直接抛 `SecurityException`，且这一行没被 `runCatching` 包住 → 异常冒泡杀死 Service 所在进程 → App「自动退出」。
- `RECORD_AUDIO` 虽在 `permission/PermissionSpec.kt` 登记，但手札 UI（`MemoScreen` / `MemoDetailScreen`）**从未弹出过运行时申请**。点录音即崩。

**涉及文件**：
- `ui/memo/MemoViewModel.kt:231` `startRecording`
- `data/attachment/RecordingService.kt:54` `startForeground`（未保护）
- `ui/memo/MemoDetailScreen.kt:213` `onRecord` 直接调
- `ui/memo/MemoScreen.kt:427` 新建「音频手札」也会直接 `startRecording`

**修复方向（待做，本次未动）**：
1. 录音前用 `PermissionManager.isGranted(RECORD_AUDIO)` 判断；未授权则通过 `ActivityResultContracts.RequestPermission` launcher 在 `MemoDetailScreen` / `MemoScreen` 申请，授权后再 `startRecording`。
2. 把 `startForeground` 也纳入 `runCatching` 兜底，异常时 `stopSelf()` 而非杀进程。
3. 权限被永久拒绝时给出「跳设置页」引导（复用 `PermissionManager.appDetailsIntent()`）。

## 问题 2 · 天气「用手机本机定位」的实际情况　🟡 中

**用户原话**：天气看是否可以直接联网获得，城市地址，可以使用手机自己的信息定位。

**现状（已读代码确认）**：
- 「联网获取 + 手机定位」**其实已经实现**：
  - 预报：`data/remote/weather/OpenMeteoService`（免 Key 联网取）。
  - 定位：`data/location/CityResolver.kt` 用系统 `LocationManager.getLastKnownLocation` 拿坐标 + `Geocoder` 反编码成城市名（如「长沙 · 岳麓区」）。
- **缺的环节**：必须授权 `ACCESS_COARSE_LOCATION` 才有坐标；没授权或拿不到 → 落到 `NeedManualPick` 状态，UI 让手动选城市（设计上**不编默认城市**）。
- **隐患**：`getLastKnownLocation` 在「刚安装、系统从没缓存过位置」的机器上会返回 `null` → 即便给了权限也定位不到 → 一直要手动选。
- `COARSE_LOCATION` 在 `PermissionSpec` 登记，但 `PermissionManager` 只在「设置页 / 提醒就绪度」里用，`PermissionManager.kt` 没有给 UI 用的 `RequestPermission` 封装，当前也未发现 onboarding 弹定位权限的入口。

**用户期望**：装上就自动用本机定位出天气，尽量少手动。

**修复方向（待做，本次未动）**：
1. 确认 / 补上 `COARSE_LOCATION` 的运行时申请引导（接 `PermissionManager` + `RequestPermission` launcher）。
2. 把 `lastKnownLocation` 升级为「拿不到就 `requestLocationUpdates` / `getCurrentLocation` 取一次实时定位」——仍走 `LocationManager`，避开 `FusedLocationProvider`（GMS），照顾荣耀等无 GMS 机型。
3. 仍拿不到才回退 `NeedManualPick`。

## 问题 3 · 每页应可向上滑动展现完整背景色　🟢 体验

**现象**：部分页内容短，背景只露出视口这一截渐变，向上滑不动，看不到完整底色。

**现状（已读代码确认）**：
- 背景由 `ui/theme/AppBackground.kt` 画在最外层 `fillMaxSize()` 的 `Box` 上，是**视口固定层**。
- 各页面内容在 `weight(1f)` 区域内；可滚动页（如日历 `LazyColumn`）滚动时背景不动，短内容页根本无法滚动。
- 渐变 `brushFor(colorKey, dark)` 是纵向渐变，固定铺满视口。

**用户期望**：每一页都能向上滑，把整段背景色 / 渐变完整露出来（背景随页面内容纵向延伸）。

**修复方向（待做，本次未动）**：
- 把背景层从「视口固定」改为「随页面内容高度延伸」：内容区外包一层 `verticalScroll`，背景与内容同高，上滑即露出更多背景。
- 需逐页评估，避免与日历 / 手札已有的滚动容器冲突（可能要区分「页级背景滚动」与「列表内滚动」）。
